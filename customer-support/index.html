Method by Jonathan Duque

These scores are research-based: public documentation, repository data, licence files and independent reviews, collected on 2026-11-18. No hands-on tests have been run yet; the planned protocol is on the methodology page.

Customer support is the queue that arrives with a cost already attached. The owner hands off a narrow job: use the help-centre material to answer routine questions, keep the conversation in the inbox, and send anything outside that material to a person. A useful system should know the difference between a documented answer and a plausible guess. It should also leave a human with the context needed to take over.

The expensive failure here is a confident wrong reply. It can promise a refund, misstate a product rule, or turn a small account issue into a public complaint. A second failure is quieter: a bot that answers but drops the conversation, so a person has to reconstruct what happened from scattered messages.

The owner-fit checks matter in a particular order. Approval points matter because an answer can change a customer relationship even when it does not change a database. The data boundary matters because tickets may contain contact details, order history, or information copied from an internal article. Setup burden matters because support is a daily operation, not a one-off demo. Running cost matters after the workflow is useful, since a growing message volume can turn model calls and hosting into a monthly surprise.

Dify, Langflow, n8n, Zammad and Sim document approval or human-in-the-loop paths in the evidence collected for this function. Zammad's Writing Assistant inserts an AI suggestion into a reply only after the agent clicks Approve. Sim connects to Zendesk and Intercom so a workflow agent can read and update tickets, and its Human block pauses a run until a person responds. FreeScout's free AI Integration module drafts replies and summarises conversations for the person working the inbox; that is agent assist, not autonomous replies, and the evidence collected records no approval value for it. Typebot documents human takeover through a Chatwoot block, but the evidence collected does not document an approve-before-send step. That distinction matters more here than a polished chat window. A human should approve replies that fall outside the supplied material, refunds or credits, policy exceptions, and any action that changes a customer record.

In this edition the evidence shows documented capabilities, owner-fit facts, repository health and licence clarity. It does not show how accurately any tool answers the same help-centre questions in a live run, how often it escalates, or whether its handoff feels good to customers. Those questions belong to the planned hands-on protocol, not today's score.
