Recopilación y fuentes

Fecha de recopilación: 2026-11-18.

Las puntuaciones salen de evidencia de investigación: documentación pública, datos de repositorios, archivos de licencia y reseñas independientes. El índice usa puntuaciones de 0 a 100 con punto decimal.

Los datos los recopilan scripts y asistentes de investigación con IA que trabajan según este método, a partir de las fuentes públicas enlazadas en cada fila; las puntuaciones salen de la fórmula de esta página. Reporta los errores por el canal de correcciones.

Inclusión y etiquetas

Una herramienta debe documentar el trabajo indicado con una fuente oficial, ser autoalojable (self-hosted), tener un lanzamiento en los últimos seis meses, pasar los filtros de salud del repositorio y de licencia, y cumplir el mínimo de la página. Lo que no se sabe queda como desconocido. Código abierto aprobado por la OSI, fair-code, código fuente disponible y licencia mixta son etiquetas distintas; código abierto (open source) se usa solo para las herramientas con la etiqueta de la OSI, también en expresiones como «agentes de IA de código abierto».

Algunas herramientas del ranking no tienen una función de IA integrada. Se incluyen porque su documentación cubre el trabajo del negocio y ofrecen una API que un agente puede operar; cada una está señalada en su fila.

Etiquetas

Cada etiqueta, salvo Favorita de Jonathan, sale de una sola regla aplicada a datos con fecha. Cuando faltan los datos de una etiqueta, esta no se muestra, y la ausencia de una etiqueta no es un hallazgo negativo. Ninguna etiqueta se paga y ninguna cambia una puntuación ni el orden de una lista.

  • Favorita de la comunidad (estrellas en GitHub): el repositorio de GitHub del proyecto tenía al menos 100,000 estrellas el 2026-11-18. Una estrella es el marcador de un usuario de GitHub; mide atención, no calidad ni ajuste a tu negocio, y no cambia ninguna puntuación ni orden.
  • En ascenso en GitHub: entre una fecha de captura anterior y 2026-11-18 (con 90 a 100 días de diferencia), el número de estrellas del repositorio en GitHub, tal como lo registramos en ambas fechas, creció en al menos 1,000 estrellas y en al menos un 10 por ciento del conteo anterior. Mide atención, no calidad, y no cambia ninguna puntuación ni orden.
  • Mantenimiento activo: el proyecto publicó al menos 6 versiones estables en los 180 días hasta 2026-11-18, la más reciente dentro de los 60 días previos a 2026-11-18. Si un proyecto no publica versiones en GitHub, cuentan en su lugar las etiquetas de versión estable de su propio repositorio; las versiones preliminares, los candidatos a versión, las betas y las versiones solo de charts nunca cuentan.
  • Licencia OSI: el archivo de licencia del repositorio del proyecto nombra exactamente una licencia, y esa licencia está aprobada por la Open Source Initiative. Las herramientas fair-code, de código fuente disponible y de licencia mixta no llevan esta etiqueta.
  • Docker en un comando: la documentación del propio proyecto, leída el 2026-11-18, inicia la edición autoalojada con un único comando oficial docker run o docker compose up.
  • Plan gratuito en la nube: el servicio alojado del propio proyecto ofrecía un plan de $0 sin límite de tiempo el 2026-11-18; una prueba gratuita no cuenta, y los límites del plan están en la línea de costo de operación.
  • Listo para MCP: la documentación del propio proyecto, leída el 2026-11-18, describe un servidor MCP que el proyecto distribuye o mantiene y que funciona con la edición autoalojada, de modo que un asistente de IA puede usar la herramienta mediante el Model Context Protocol. Una herramienta que solo puede llamar a otros servidores MCP no lleva esta etiqueta.
  • Favorita de Jonathan: Jonathan Duque usa esta herramienta en su propio trabajo y la añadió él mismo a su lista corta. Es la única etiqueta que no se calcula; ningún proyecto puede pagarla ni solicitarla, y no cambia ninguna puntuación ni orden. Jonathan Duque construye sistemas de agentes para negocios, a veces con herramientas marcadas así.

La puntuación que se muestra es el total ponderado, redondeado a un decimal (las mitades se redondean hacia arriba). Los empates se resuelven con evidencia de investigación, ajuste para dueños de negocio, salud del proyecto y claridad de la licencia, en ese orden; los empates exactos comparten posición. Los tramos son fijos y globales: la puntuación de una herramienta no cambia cuando otra se suma a la lista, y el número de estrellas se muestra pero no se puntúa.

Cómo se puntúa cada componente

Toda subpuntuación es un número entero. Aquí se resumen las reglas completas para que cualquiera pueda recalcular una fila.

Filtros: la evidencia mínima para entrar al ranking

Una herramienta entra al ranking de una función solo si pasa todos los filtros. Cada incumplimiento queda registrado y la herramienta no se muestra con puntuación en esa función.

FiltroRegla
G1 En la listaLa herramienta está en el índice y no figura en la lista de exclusiones.
G2 Trabajo documentadoLa función es una de las que la herramienta declara, con una frase sobre lo que hace para ese trabajo y al menos una fuente oficial.
G3 Autoalojable y con lanzamiento recienteLa herramienta puede autoalojarse y tiene un lanzamiento en los últimos seis meses. Las cuatro clases de licencia son elegibles y se etiquetan con exactitud.
G4 Etiqueta de licenciaLa clase es OSI, fair-code, código fuente disponible o mixta, con el nombre de la licencia y una fuente. Una clase OSI necesita exactamente un ID de licencia aprobado en la lista SPDX (3.29.0); fair-code y código fuente disponible no deben tener ningún ID aprobado por la OSI.
G5 Datos de saludDatos de GitHub del repositorio correcto, con la fecha del último commit.
G6 LanzamientosAl menos un lanzamiento en los últimos 180 días, o el proyecto no publica lanzamientos en GitHub (en ese caso decide G3).
G7 Sin archivarEl repositorio no está archivado.
G8 Mismo repositorioGitHub reporta el mismo nombre de repositorio que figura en el índice.
G9 Mínimo por páginaUna función muestra posiciones solo si al menos 3 herramientas pasan de G1 a G8.

Una fuente oficial es una página del sitio de la propia herramienta (página de inicio, documentación o página de autoalojamiento) o de su repositorio de GitHub.

Protocolo de pruebas prácticas

Las pruebas prácticas están planificadas; aún no hay fecha. Cada función recibirá una tarea realista de dueño de negocio, ejecutada de la misma forma con cada herramienta evaluada. Los criterios de éxito o fallo se publican antes de cualquier ejecución. Cada ejecución fija la versión de la herramienta, la imagen del contenedor, el modelo de IA y la fecha; usa solo datos de ejemplo; se repite tres veces; y sus resultados se publican con los registros.

Método del panel

El panel se presenta, nunca se puntúa. Contiene 22 respuestas en total, todas recopiladas el 2026-11-18, de interfaces gratuitas para consumidores: Gemini en una cuenta de consumidor con sesión iniciada, en chat temporal; Gemini en la aplicación web sin sesión iniciada; y Perplexity en la aplicación web sin sesión iniciada (incluida una sesión sin iniciar sesión, con la interfaz en español, desde una IP de Colombia). La ruta de Perplexity con sesión iniciada no estaba disponible. No se recopilaron respuestas de ChatGPT ni de Google AI Overview: ChatGPT mostró una comprobación de Cloudflare y Google AI Overview no tuvo una sesión manejada por una persona. Para cada función, la página da una línea por motor e interfaz con su propio número de respuestas y su fecha, indica en cuántas de las respuestas de cada interfaz se nombró una herramienta del índice ("nombrada en k de n respuestas", contado por interfaz y nunca agrupado ni expresado como porcentaje), y enumera los motores que no se recopilaron, con el motivo. Las respuestas recopiladas con sesión iniciada en una cuenta de consumidor pueden estar personalizadas: las respuestas de Gemini con sesión iniciada vinieron de la cuenta propia de Jonathan Duque, que tiene historial previo de chats sobre temas relacionados, por lo que no son una muestra neutral, y la página lo dice. Una función sin respuestas muestra qué motores están pendientes.

Independencia

Jonathan Duque trabaja en una empresa de software SEO. Open Agent Index es su proyecto personal: su empleador no interviene en lo que se incluye ni en cómo se puntúa, y ninguno de sus productos está evaluado.

Fuentes y atribución

Las cifras de los repositorios (estrellas, fechas de lanzamientos y de commits) se leyeron en la API de GitHub el 2026-11-18. Open Agent Index no está afiliado a GitHub ni cuenta con su respaldo.

Correcciones

Quienes mantienen un proyecto pueden solicitar la corrección de un valor, una fuente o una etiqueta mediante los issues de GitHub, con la plantilla de corrección: la URL de la página, el valor, una fuente que muestre el valor correcto y una etiqueta. Jonathan Duque revisa cada solicitud frente a la fuente citada; una solicitud no garantiza que el resultado cambie. Las correcciones aceptadas quedan fechadas en el registro de cambios de esta página.
