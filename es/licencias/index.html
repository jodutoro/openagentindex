Licence classes

  • Código abierto aprobado por la OSI (83) Uso empresarial generalmente permitido según sus condiciones.
  • Fair-code (1) Uso gratuito con posibles límites comerciales.
  • Código fuente disponible (source-available) (15) Código legible con condiciones adicionales.

Código abierto aprobado por la OSI

El código autoalojable está cubierto por una licencia aprobada por la Open Source Initiative. Su definición exige, entre otras cosas, acceso al código fuente, permiso para crear obras derivadas y que la licencia no limite el uso del programa en un negocio.

Qué significa para tu negocio

  • Por lo general, puedes ejecutar la herramienta para tu negocio, incluso en tu propia infraestructura.
  • Normalmente puedes modificarla y compartir la versión original o modificada, sujeto a las condiciones de esa licencia.
  • La clase OSI no impide por sí sola alojarla para un cliente o vender un servicio basado en ella. Revisa la licencia exacta y cualquier archivo empresarial, extensión, marca o término para servicios alojados.
  • El proyecto puede cambiar las versiones futuras o añadir componentes con otra licencia. Revisa la versión que piensas instalar.

Licencia mixta

Distintas partes del repositorio autoalojable tienen términos distintos. En este índice, esto puede significar un núcleo de código abierto con directorios empresariales bajo una licencia comercial, o un repositorio que combina varias familias de licencias.

Qué significa para tu negocio

  • Tal vez puedas usar el núcleo en tu negocio, pero las partes empresariales pueden exigir una licencia pagada para producción.
  • Algunas partes restringidas pueden permitir modificaciones y pruebas internas, pero limitar el uso en producción, la reventa o el alojamiento administrado.
  • Identifica qué directorios, imágenes, paquetes y funciones usa tu instalación. No supongas que la licencia del núcleo cubre todo.
  • Revisa de nuevo el repositorio y sus licencias al actualizar. Los límites pueden cambiar entre versiones.

Código fuente disponible

El código fuente se puede leer, pero la licencia no está aprobada por la OSI. Los proyectos de esta clase tienen condiciones adicionales que pueden limitar actividades como ofrecer servicios competidores, usar entornos multiusuario, cambiar la marca o entregar el software como servicio alojado.

Qué significa para tu negocio

  • Tu uso interno puede estar permitido, pero depende de la licencia específica y sus condiciones.
  • Tal vez puedas modificar el código. Revisa si la licencia permite redistribuirlo, trabajar para clientes o hacer cambios comerciales.
  • La reventa, ofrecerlo como servicio alojado o quitar la marca pueden estar restringidos. Invoice Ninja, Dify, Open WebUI y Typebot tienen condiciones registradas distintas.
  • Lee la licencia vigente, sobre todo las definiciones de uso en producción, uso comercial, uso competidor y servicio alojado, antes de ponerlo en marcha.

Fair-code

Fair-code describe un modelo de software, no una licencia estándar. El código es público y el software suele ser gratuito, pero sus autores imponen límites comerciales a la forma en que otros pueden venderlo o comercializarlo.

Qué significa para tu negocio

  • Los proyectos fair-code pueden usarse de forma privada y dentro de una empresa, pero el uso comercial puede tener límites.
  • Ejecutar la herramienta para tus propias operaciones puede estar permitido. Alojarla para clientes, cobrar por el acceso o prestar consultoría alrededor de ella puede requerir permiso o un acuerdo comercial.
  • La modificación y la redistribución dependen de la licencia concreta del proyecto. Revisa los archivos de licencia y los términos empresariales.
  • Trata cada herramienta fair-code por separado. Las versiones futuras pueden tener otros términos.
